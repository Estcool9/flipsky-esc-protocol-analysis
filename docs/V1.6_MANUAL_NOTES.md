# V1.6 application manual — analysis notes

**Document:** Flipsky ESC Tool V1.6 User Manual  
**Document length:** 90 pages  
**Manual version history entry:** V1.6, dated 2025-11-25  
**Source:** user's Nextcloud project folder, Flipsky ESC Tool V1.6

These notes capture details useful to reverse-engineering the V1.6 and V1.7 applications. They are extracted from the manual text; page images and figure layouts have not yet been inspected.

## 1. Product and application scope

The manual states that Flipsky ESC Tool V1.6 is intended for the FT ESC family. It lists supported/current products including FT85BS and FT85BS 2.0, FT85BD, FT85RS, FT60BD, FT85KS, FT85GS, FT85CS_WP and FT110BS.

The application manual describes serial USB connection, CAN multi-ESC discovery, motor setup, control setup, live testing and display, factory reset, firmware update and configuration import/export.

## 2. Firmware-update workflow described by the manual

The V1.6 manual's documented workflow is:
1. Connect to the ESC over USB.
2. Select "Enter bootloader".
3. The manual describes a fixed-frequency red LED blink as the bootloader indication.
4. Reconnect the ESC in bootloader mode.
5. Select the corresponding firmware and start flashing.
6. A steady green and blue LED indication after the described red/green LED blink sequence is given as the success indication.
7. Reconnect to the ESC after the update.

For dual ESC products such as FT85BD, the manual explicitly says to update the master and slave independently using each board's USB connection.

This manual summary is not an instruction to flash anything during this static-analysis project. No firmware has been written to an ESC.

## 3. CAN multi-ESC topology

The manual identifies the USB-connected ESC as the master and units connected over CAN as slaves. It describes a theoretical maximum of 253 slave CAN devices, excluding reserved/special IDs 0 and 255, while recommending no more than 8 slaves in practical use.

The manual also discusses CAN termination: keep termination at the first and last ESC in the chain, and remove termination resistors from intermediate devices.

These are manual-reported installation details, not a test performed in this project. The UART protocol's CMD 0x10 forwarding envelope is described separately in [FTESC_UART_PROTOCOL_V1.6.md](FTESC_UART_PROTOCOL_V1.6.md).

## 4. Input-signal modes

The manual lists OFF, UART, PPM, ADC and PAS as Input Signal Type options, with OFF as the documented default.

This matters for interpreting the V1.6 UART command specification:
- commands 0x03-0x06 and 0x20, 0x25-0x27 are documented for OFF mode;
- CMD 0x02 has a UART-mode control meaning;
- the same CMD 0x02 has a PAS-mode gear meaning in V1.6 section 3.1.18.

Mode is therefore part of the command interpretation context. A command byte cannot always be decoded correctly without the ESC's configured input-signal mode.

## 5. V1.6 application-manual revision history

The manual's V1.6 entry dated 2025-11-25 describes product and application additions, including waterproof FT85CS_WP and high-voltage FT110BS; five speed gears with the upper two reserved for PAS mode; AS5600_IIC and TLE5012_SPI encoders; OpenMode motor startup; additional voltage/current/thermal limits and battery parameters; motor_conf and control_conf save/load features; emergency-switch and safety-start options; and PAS dual-Hall-sensor, startup-boost and idle-current features.

This is manual history, not evidence that each feature maps to a particular UART opcode.

## 6. Cautions and interpretation limits

- The user manual is application-facing and may combine several ESC hardware variants.
- UI availability does not prove a specific wire-level command.
- Bootloader LED descriptions are manual text, not validated on live hardware in this project.
- Firmware flashing, resets, current control and motor commands remain out of scope for physical execution.
